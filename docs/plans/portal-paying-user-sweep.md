# Portal paying-user sweep

## Purpose
This file is the source of truth for the portal-only product sweep.

The goal is to behave like a paying business owner using the portal day to day, not to get distracted by low-value route trivia.

A workflow or service is not done until all of these are true:
- it was used like a real operator would use it
- visible friction was written down
- any fix was linked to the file(s) changed
- validation was recorded

## Rules
- Stay in `portal` unless a portal flow hard-depends on another surface.
- Prefer actual usage flows over theoretical code cleanup.
- Do not declare a section complete because the route exists.
- Do not get stuck on one bug forever; record it, fix it if high-value, then continue sweep coverage.
- Keep notes short, concrete, and user-facing.

## Status key
- `todo`: not yet used in a serious pass
- `active`: currently being used/audited
- `fixed`: friction found and addressed
- `verified`: used after fix and no obvious friction remains in this pass
- `blocked`: cannot complete without external state, credentials, seed data, or a separate dependency

## Execution loop
For each row below:
1. Open the surface like a business owner would.
2. Try the obvious actions, secondary actions, and one edge-case action.
3. Record friction in plain language.
4. Patch only the highest-value issues from that pass.
5. Validate targeted files and record outcome.
6. Move on; come back later for another pass if needed.
